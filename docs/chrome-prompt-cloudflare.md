أنت تعمل داخل متصفحي وأنا مسجّل الدخول في حساباتي. المهمة: إنهاء بنود لوحة Cloudflare المتبقية لموقع إحكام (ihkaam.app، يعمل على Cloudflare Pages). اقرأ كل شيء قبل أن تبدأ.

## قواعد لا تُخرق
1. الأصل قراءة فقط. قبل كل تغيير اكتب لي بالضبط: أين ستضغط، وما القيمة القديمة، وما الجديدة، ثم انتظر كلمة «نعم» مني. لا تجمع عدة تغييرات في موافقة واحدة.
2. ممنوع بلا إذن صريح: حذف أي شيء، Purge Everything، نقل نطاق أو إلغاؤه، تغيير سجلات DNS غير المذكورة هنا، تغيير الخطة أو الفوترة، إنشاء مفاتيح API.
3. لا تعرض في ردودك أي سرّ: رابط Deploy Hook، رمز، مفتاح، كلمة سر، قيمة متغير بيئة. اذكر فقط «موجود/غير موجود».
4. إن ظهر تحقق بخطوتين أو كابتشا أو نافذة فوترة أو شيء لا يطابق وصفي، فتوقف واسألني بدل التخمين.
5. أسماء القوائم بالإنجليزية كما تظهر في اللوحة؛ إن لم تجد قائمة في مكانها فابحث بمربع البحث أعلى اللوحة.
6. في نهاية كل مرحلة اكتب تقريراً من أسطر قصيرة: تم / لم يتم / يحتاج مني.

## المرحلة 1: الآن (لا تحتاج نشراً)
**1.1 إعدادات البناء (قراءة فقط):** Workers & Pages ← مشروع الموقع ← Settings. تأكد أن Build command = `npm run build` وBuild output directory = `dist` وRoot directory فارغ. وتأكد أن المتغيرات `VITE_SUPABASE_URL` و`VITE_SUPABASE_ANON_KEY` و`NODE_VERSION` موجودة في Production وفي Preview (موجود/غير موجود فقط، بلا قيم). إن كان `NODE_VERSION` ناقصاً فاقترح إضافته بالقيمة `22` من نوع Text وانتظر موافقتي. وإن لم تجد قسم Build configuration فالمشروع Direct Upload: أخبرني ولا تغيّر شيئاً.

**1.2 Web Analytics (بند 32):** Workers & Pages ← المشروع ← Metrics ← Web Analytics ← Enable. قبل التفعيل افتح على النطاق Analytics & Logs ← Web Analytics وتأكد أنه غير مفعّل هناك أيضاً (لا يُفعَّل من مكانين). فعّله من مكان واحد فقط بعد موافقتي.

**1.3 إعدادات تتعارض مع CSP (بند 34):** على النطاق ihkaam.app:
- Speed ← Optimization ← Content Optimization ← **Rocket Loader**: يجب أن يكون Off.
- Scrape Shield ← **Email Address Obfuscation**: يجب أن يكون Off.
- Security ← Bots ← **Bot Fight Mode**: أخبرني بحالته فقط، لا تغيّره.
أخبرني بالحالة الحالية لكل واحد، وغيّر ما هو On إلى Off بعد موافقتي.

**1.4 فحص DNS لـwww (قراءة فقط، لا تنشئ قاعدة بعد):** DNS ← Records. أخبرني: إلى أين يشير سجل `www` بالضبط (النوع والهدف)، وهل هو Proxied (غيمة برتقالية) أم DNS only، وهل يوجد سجل لنطاق فرعي مثل `app` أو `portal`. السبب: www يعرض الآن تطبيق بوابة المعاهد المنشور على Netlify، وتحويله إلى الموقع التسويقي يقطع وصول المعاهد إليه. **لا تنشئ Redirect Rule للـwww في هذه المرحلة مهما بدا ذلك بسيطاً.**

## المرحلة 2: بعد أن أخبرك أنني نشرتُ النسخة الجديدة
**2.1 فحص CSP على الموقع الحي:** افتح https://ihkaam.app في تبويب جديد، وافتح الكونسول، وتنقّل بين: الرئيسية، `/ihkaam`، صفحة ميزة، مقال من `/blog`، `/request`، `/checkout`، `/admin/login`. انسخ لي حرفياً كل سطر فيه `Content Security Policy` أو `Refused to`. المتوقع: لا شيء. لا تغيّر ترويسات ولا ملف `_headers`.

**2.2 Search Console:** افتح Search Console ← Add property ← **Domain** ← `ihkaam.app`. انسخ سجل TXT وأضفه في Cloudflare: DNS ← Records ← Add record، النوع TXT والاسم `@` والقيمة المنسوخة (بعد موافقتي)، ثم Verify. بعدها Sitemaps ← أضف `sitemap.xml` ← Submit، واحذف أي خريطة مسجّلة على عنوان www إن وُجدت (بعد موافقتي). وفي URL inspection اطلب الفهرسة (Request indexing) لهذه الروابط واحداً واحداً: `https://ihkaam.app/` و`/ihkaam` و`/blog` و`/about`؛ وقبل كل طلب افتح View crawled page ← HTML وتأكد أنك ترى نص الصفحة لا صفحة فارغة.

## المرحلة 3: Deploy Hook للنشر المجدول (اختيارية، اسألني قبل أن تبدأ)
الغرض: مستودع GitHub فيه workflow باسم `publish-scheduled.yml` يستدعي secret باسم `CF_DEPLOY_HOOK` كل يوم 03:00 UTC ليبني الموقع وينشر المقالات المجدولة.
1. Cloudflare ← Workers & Pages ← المشروع ← Settings ← Builds ← Deploy hooks ← Add: الاسم `scheduled-publish` والفرع Production (أخبرني باسمه قبل الإنشاء).
2. **لا تعرض الرابط في ردك.** انسخه إلى الحافظة ثم افتح تبويب GitHub ← المستودع ← Settings ← Secrets and variables ← Actions ← New repository secret، الاسم `CF_DEPLOY_HOOK`، والصق القيمة هناك فقط. اسألني أولاً عن اسم المستودع.
3. بعد الحفظ أخبرني فقط أن السر موجود، ثم افتح تبويب Actions ← Publish scheduled ← Run workflow يدوياً **بعد موافقتي**، وانقل لي نتيجة التشغيل.
