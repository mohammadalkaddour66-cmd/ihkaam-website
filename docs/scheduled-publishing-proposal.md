# اقتراح: نشر المقالات المجدولة تلقائياً بلا رصيد ولا push

كُتب: 2026-11-21. **وافق المالك (2026-11-21) ونُفِّذ الكود** (القسم الأخير: «ما نُفِّذ»). يبقى على المالك إعداد Deploy Hook ودمج الفرع في `main`.

## المطلوب

تجهيز دفعات مقالات مسبقاً، فيظهر كل مقال في تاريخه وحده، وتتحدّث الخريطة (sitemap.xml) ويُرسَل IndexNow، بلا جلسة كلود ولا push يدوي لكل مقال.

## الوضع اليوم (من الكود)

- النشر = تحويل `status` من `'draft'` إلى `'published'` وكتابة التاريخ، ثم push. تُحوَّل المقالات في `src/data/blogContent.js` فقط.
- Cloudflare Pages مربوط بالمستودع على GitHub، ويبني بـ`npm run build` عند كل push.
- Cloudflare Pages لا يملك جدولة بناء. لا يبني إلا عند push أو عند استدعاء رابط «Deploy Hook».
- IndexNow سكربت يدوي (`scripts/indexnow.mjs`) يُشغَّل بعد النشر.
- **ملاحظة تخصّ الموضوع:** نص المسودات مُحزَّم اليوم داخل ملف JS الذي يحمّله الزائر (`dist/assets/blogContent-*.js`)، ويقرؤه من يفتحه. أي حل للمقالات المجدولة يجب أن يخرجها من الحزمة حتى يوم نشرها.

## التوصية: GitHub Actions يوقظ بناء Cloudflare كل صباح

مجاني بالكامل (0 رصيد)، ويبقى كل شيء داخل المستودع.

```
كل يوم 03:00 UTC (06:00 دمشق)
  1. الفحص: هل في المستودع مقال تاريخه اليوم أو قبله ولا يظهر بعد في https://ihkaam.app/sitemap.xml؟
     لا ← ينتهي في ثوانٍ، ولا بناء.
  2. نعم ← POST إلى Deploy Hook في Cloudflare: يبني الموقع بتاريخ اليوم، فيدخل المقال.
  3. ينتظر حتى يظهر رابط المقال في الخريطة الحيّة (حتى 15 دقيقة).
  4. node scripts/indexnow.mjs /blog/<slug> /blog
```

### التغيير في الكود (مرة واحدة، يطلب جلسة واحدة)

1. **قاعدة التاريخ:** المقال يظهر حين `date ≤ تاريخ البناء` بتوقيت دمشق. غير ذلك «مجدول»: لا صفحة، ولا في الخريطة، ولا في llms.txt، ولا في «مقالات ذات صلة»، ولا في بطاقة أداة مرتبطة (`config/tools.js` يتحقق من وجود المقال، فتسقط حاجة «أضفه يوم نشره» يدوياً).
2. **خروج المجدول من الحزمة:** إضافة صغيرة لـVite تستبدل ملفات المقالات المستقبلية بمدخل فارغ وقت البناء.
3. **تاريخ تجريبي:** متغير `SITE_TODAY=2026-12-08 npm run build` يحاكي يوم النشر محلياً، فنرى المقال والخريطة قبل أن يحدث شيء حقيقي.
4. **فحص المجدول قبل موعده:** أمر `npm run check:scheduled` يبني بتاريخ بعيد ويشغّل `audit-seo` على المقالات المجدولة (العنوان، والوصف، والمصادر، والروابط). وإلا بقي المقال بلا فحص حتى صباح نشره.
5. **ملفان جديدان:** `scripts/due-posts.mjs` و`.github/workflows/publish-scheduled.yml`.

### ما تفعله أنت (10 دقائق، مرة واحدة)

1. Cloudflare ← Workers & Pages ← مشروع الموقع ← Settings ← Builds ← **Deploy hooks** ← Add: الاسم `scheduled-posts`، والفرع `main`. انسخ الرابط.
2. GitHub ← المستودع ← Settings ← Secrets and variables ← Actions ← New secret باسم `CF_DEPLOY_HOOK` والقيمة الرابط. الرابط سرّ: من يملكه يبني موقعك.
3. تأكد أن Actions مفعّل في المستودع (Settings ← Actions ← Allow).

## البدائل ولماذا ليست الأولى

| البديل | ما يعيبه |
|---|---|
| Actions يبني ويرفع بنفسه (Wrangler) | يحتاج رمز API وحساب Cloudflare، ويتعارض مع مشروع Pages المربوط بـGit (الرفع المباشر مشروع آخر). أعقد بلا فائدة |
| Cloudflare Worker بمؤقت (Cron Trigger) يستدعي الـHook | مجاني، لكن كوداً خارج المستودع، وبلا فحص «هل في مقال مستحق» ولا IndexNow بعد النشر |
| بناء يومي أعمى بلا فحص | يستهلك بناءً من حصة Cloudflare المجانية (500 في الشهر) كل يوم بلا حاجة، ولا يرسل IndexNow |

## حدود يجب أن تعرفها

- **التأخير:** مؤقتات GitHub لا تضمن الدقيقة، وقد تتأخر عشرات الدقائق في أوقات الازدحام. «في تاريخه» تعني صباح ذلك اليوم لا ساعة بعينها.
- **توقف المؤقت:** في المستودعات **العامة** يوقف GitHub المؤقتات تلقائياً بعد 60 يوماً بلا أي نشاط في المستودع. عملك المنتظم (commits) يكفي. إن توقفت أشهراً فاضغط Enable من تبويب Actions، أو أضيف مهمة شهرية بسيطة تحفظ النشاط.
- **الدقائق:** المستودع العام بلا حد. الخاص له 2000 دقيقة شهرياً، وهذا يستهلك نحو دقيقة في اليوم (30 دقيقة).
- **الفشل:** إن فشلت الخطوة يرسل GitHub بريداً بالفشل. المقال يبقى مجدولاً ويظهر في اليوم التالي بتأخير يوم.
- **الدقة تحتاج جلسة واحدة الآن:** كتابة المقالات نفسها وتجهيزها مسبقاً تستهلك رصيداً مرة (عند التحضير). ما بعدها، النشر مجاني.

## ما نُفِّذ (2026-11-21)

| الملف | الدور |
|---|---|
| `scripts/lib/blog-schedule.mjs` | قاعدة الظهور: `status ≠ 'draft'` و`date ≤ اليوم بتوقيت دمشق`، ومتغير `SITE_TODAY` للمحاكاة |
| `vite.config.js` | يُفرغ ملف المقال غير الظاهر (فلا نص في حزمة JS)، ويعرّف `__LIVE_POSTS__` |
| `src/data/blogContent.js` | يحمّل كل ملفات `blog/` تلقائياً (إضافة مقال = ملف واحد بلا قائمة)، وفلتر الظهور بالتاريخ، و`BLOG_SCHEDULED` |
| `src/config/tools.js` | يربط أداة الشهادة بمقالها، ويظهر الرابط وحده يوم نشره (انتهت خطوة «أضفه يوم نشره») |
| `scripts/due-posts.mjs` | المقالات المستحقة وغير الظاهرة في الخريطة الحية، وانتظار ظهورها |
| `.github/workflows/publish-scheduled.yml` | المؤقت اليومي 03:00 UTC (06:00 دمشق) |
| `scripts/check-scheduled.mjs` (`npm run check:scheduled`) | فحص ثابت لروابط المقالات الأمامية، ثم بناء بتاريخ بعيد وaudit-seo وaudit-links |
| `scripts/audit-links.mjs` | يفشل الآن إن وُجد رابط داخلي إلى مقال غير موجود |

**اختُبر محلياً:** بناء اليوم لا يحوي المقالين المجدولين (لا صفحة، ولا في الخريطة، ولا نصهما في JS)، وبناء `SITE_TODAY=2026-12-08` يخرج بـ82 صفحة و73 رابطاً مع مقال الشهادة ورابطه من أداة الشهادة، و`audit-seo` و`audit-links` نظيفان. **لم يُختبر:** المؤقت نفسه، وDeploy Hook، وIndexNow من Actions (يحتاج دمج الفرع وإعداد السر).

## طريقة العمل بعد الآن

1. اكتب المقال في `src/data/blog/<slug>.js` بـ`status: 'published'` وتاريخ النشر المراد. تاريخ مستقبلي = مجدول. (`'draft'` = لا يُنشر وحده أبداً.)
2. `npm run check:scheduled` قبل الـpush (الروابط بين المقالات، وaudit-seo، وaudit-links على المجدول).
3. push واحد للدفعة كلها. بناء Cloudflare يستبعد المجدول. وفي صباح كل تاريخ يظهر المقال وحده.
4. للمعاينة: `SITE_TODAY=2026-12-08 npm run build` (في PowerShell: `$env:SITE_TODAY='2026-12-08'; npm run build`).
5. `node scripts/due-posts.mjs --dry-run` يعرض كل مقال وحالته (يظهر / مجدول / مسودة).

## حدود إضافية

- lastmod لصفحة `/blog` في الخريطة يُحسب من بصمة المحتوى مقابل نسخة git من `sitemap-lastmod.json`. فبعد نشر مقال بالمؤقت تبقى لـ/blog تاريخ أي بناء لاحق حتى يُودَع الملف المحدَّث في git (نشر يدوي واحد). لا أثر على المقال نفسه: تاريخه تاريخ نشره دائماً.
- المؤقت يقرأ فرع `main` فقط، ويعمل فقط حين يكون ملف الـworkflow على `main`.
