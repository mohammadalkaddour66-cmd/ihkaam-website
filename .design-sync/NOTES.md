# design-sync notes — my-website → Ihkaam Design System

## What this repo is (and isn't)

This is a **Vite application**, not a published component library. `package.json` is
`"private": true` with no `main`/`module`/`exports`, and `dist/` holds a built
*website*. Several converter defaults assume a library, so:

- **`--entry .design-sync/ds-entry.jsx` is required on every build.** Without it the
  converter resolves `PKG_DIR` to `node_modules/my-website`, which npm never creates
  for a repo's own package, and dies on `ENOENT … my-website/package.json`.
  `ds-entry.jsx` is a hand-maintained barrel: what it exports IS the design system.
  Adding a component means editing both it and `componentSrcMap`.
- The synth-from-src fallback is deliberately not used — it would sweep in every
  section, including ones that need Supabase or a router.

## The build is three commands, not one

1. **Compile Tailwind first.** `cssEntry` points at `.design-sync/compiled.css`, which is
   *generated* and gitignored. `src/index.css` is only 7 KB of `@import "tailwindcss"`
   plus custom classes — shipping it raw loses every utility and all previews render
   unstyled. Regenerate before any build:
   ```sh
   node .ds-sync/node_modules/@tailwindcss/cli/dist/index.mjs -i src/index.css -o .design-sync/compiled.css
   ```
   (`@tailwindcss/cli` is installed into `.ds-sync/`, not the repo — the repo only has
   `@tailwindcss/vite`.)
2. `package-build.mjs … --entry .design-sync/ds-entry.jsx`
3. `package-validate.mjs ./ds-bundle`

## Fixes applied, and why

- **`src/config/landingStats.js` now imports `supabaseClient` dynamically.**
  `supabaseClient.js` throws at *module load* when `VITE_SUPABASE_*` are unset. Because
  the whole DS is one IIFE, that single top-level throw left `window.Ihkaam` empty and
  **all 16 components failed**, not just the two that use stats. The dynamic import
  moves the failure to first fetch, with a `.catch` that logs and returns `EMPTY` —
  the same handling the module already had for RPC errors. This is app source, agreed
  with the repo owner; don't revert it to a top-level import.
- **`AboutSection` is excluded** (`componentSrcMap: {"AboutSection": null}`). It imports
  `../assets/profile.png.jpg`, and the converter's esbuild loader map covers
  `.svg/.png/.woff/.woff2` but not `.jpg`. `lib/bundle.mjs` owns that map and the skill
  forbids forking it, so exclusion was cheaper than touching app code for one section.
- **Cairo is vendored.** `index.html` loads it from Google Fonts at runtime, which
  `[FONT_MISSING]` correctly flags — designs built from this DS would fall back to
  system fonts. `.design-sync/fonts/` holds the three variable woff2 subsets (arabic,
  latin, latin-ext, ~81 KB total) plus a rewritten `cairo.css`, wired via `extraFonts`.
  One file per subset serves all six weights; the files are variable, so don't be
  fooled into thinking a weight is missing.
- **`FloatingBg` uses `cardMode: "single"`.** It's `fixed inset-0`, so its stories
  escaped their grid cells (`[GRID_OVERFLOW]`).

## Known render warns (expected — not new findings)

- `[RENDER_BLANK] GlowCursor` — it renders at `opacity: 0` off-canvas until a real
  `mousemove`, so a static screenshot is legitimately blank. There is no authored
  preview that can fix this without reimplementing the component, which the skill
  forbids. Leave it.

## Re-sync risks — read before the next run

- **`compiled.css` goes stale silently.** It's gitignored and regenerated by hand. Skip
  step 1 above and you'll ship the *previous* run's utilities — the build won't warn.
  Any new Tailwind class added to a component since the last compile just won't exist.
- **`ds-entry.jsx` and `componentSrcMap` drift apart.** They're two hand-maintained lists
  of the same 16 names. A component added to one but not the other silently vanishes
  from the DS or fails to resolve.
- **Cairo is pinned to Google's v31 URLs** as of this sync. The files are vendored so
  nothing breaks, but they won't pick up upstream font updates.
- **Only `RippleButton` takes props.** The other 15 are zero-prop page sections, so the
  emitted `.d.ts` contracts are near-empty by nature, not by extraction failure. This
  repo is plain JS with no `tsconfig`, so `[DTS] parsed 0 .d.ts files` is expected —
  don't chase it.
- **`IhkaamByNumbers` / `IhkaamTrustStats` render zeros** in every preview. They fetch
  from Supabase internally and accept no props, so no authored preview can inject
  figures. Their layout and typography are still faithful.
- **Playwright must be 1.61.1** to match the cached `chromium-1228`. A different version
  fails with `browserType.launch: Executable doesn't exist`.
